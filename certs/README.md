# Сертификаты для доступа к API MAX

API мессенджера MAX (`platform-api2.max.ru`) работает по сертификату
удостоверяющего центра Минцифры. В стандартном наборе Node его нет,
поэтому соединение падает с ошибкой:

```
UNABLE_TO_GET_ISSUER_CERT_LOCALLY — unable to get local issuer certificate
```

## Как починить

Скачайте два файла и положите их в эту папку:

1. **Корневой сертификат** — https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
2. **Выпускающий сертификат** — https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt

Оба доступны на портале Госуслуг: https://www.gosuslugi.ru/crt

Файлы должны быть в формате PEM — то есть начинаться со строки
`-----BEGIN CERTIFICATE-----`. Если скачался файл в другом формате,
откройте его в текстовом редакторе и проверьте.

Расширение может быть `.pem`, `.crt` или `.cer` — подхватятся все.

После этого закоммитьте файлы и задеплойте:

```
git add certs/
git commit -m "Сертификаты Минцифры для API MAX"
bash push.sh
```

При старте в логах появится строка `[max] Загружено дополнительных
сертификатов: 2`, а следом — что MAX-бот запущен.

## Почему сертификаты лежат в репозитории

Это публичные корневые сертификаты, а не секреты: они одинаковы для всех
и открыто раздаются государством. Хранить их рядом с кодом безопасно и
удобно — не нужно ничего настраивать на сервере вручную.
